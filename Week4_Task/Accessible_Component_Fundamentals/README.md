# Accessible Components Playground

I built three common UI components **from scratch**, without any component library, and made them
accessible. That means they work with **only a keyboard** and with **screen readers**. Then I added
the same components from **shadcn/ui** to compare them with mine.

| Component      | What it does                                          |
| -------------- | ----------------------------------------------------- |
| **Disclosure** | A button that shows and hides some content            |
| **Tabs**       | A row of tabs; only one panel is visible at a time    |
| **Modal**      | A popup window that keeps focus inside until it closes |

All three follow the official rules from the
[W3C ARIA Authoring Practices Guide (APG)](https://www.w3.org/WAI/ARIA/apg/patterns/).

**Built with:** Next.js 16, React 19, TypeScript (strict mode), Tailwind CSS, shadcn/ui (Radix).

You need Node.js installed.

**1. Go to the project folder**

```bash
cd Week4_Task/Assignment_1
```

**2. Install packages** (only the first time)

```bash
npm install
```

**3. Start the app**

```bash
npm run dev
```

**4. Open** [http://localhost:3000](http://localhost:3000). It goes straight to the playground page.

To stop the app, press **Ctrl + C** in the terminal.

```bash
npx tsc --noEmit
```

If you haven't run `npm run dev` yet, run `npx next typegen` first so Next.js can create its types.

## How each component works

### Disclosure

- It uses a real `<button>`, so **Enter** and **Space** already work. No extra keyboard code is needed.
- `aria-expanded` tells a screen reader whether the content is open or closed.
- `aria-controls` points to the content the button opens.
- Closed content gets the `hidden` attribute, so it is hidden from everyone, including keyboard and
  screen reader users.
- IDs come from `useId()`, so they are always unique.

### Tabs

- Roles: `tablist` for the row, `tab` for each button, `tabpanel` for each content box.
- The selected tab has `aria-selected="true"`. Tabs and panels are linked with `aria-controls` and
  `aria-labelledby`.
- **Roving tabindex:** only the selected tab has `tabIndex=0`, and all the others have `-1`.
  So the **Tab** key stops on the tab row only once, and the next Tab goes into the panel.
  Inside the row you move with the arrow keys.
- **Arrow Right / Left** go to the next or previous tab and wrap around at the ends.
  **Home** goes to the first tab and **End** to the last.
- Moving with the arrows also **selects** the tab straight away (automatic activation).

### Modal

- It has `role="dialog"`, `aria-modal="true"` and `aria-labelledby`, which points to the title.
- It is **controlled**: the parent decides when it is open with the props `open`, `onClose`,
  `title` and `children`.
- **When it opens:**
  1. It saves the element that had focus (the "Open modal" button).
  2. It moves focus to the first field inside the modal.
- **Focus trap:** if you press **Tab** on the last element, focus jumps back to the first one.
  **Shift+Tab** on the first element jumps to the last one. So focus can't leave the modal.
- **Escape** closes it.
- **When it closes:** focus goes back to the button that opened it. This happens in the
  `useEffect` cleanup, which React runs when `open` becomes `false`.

## My version vs shadcn

The hand-built components were committed **before** shadcn was installed. Then I ran:

```bash
npx shadcn@latest init
npx shadcn@latest add dialog tabs
```

For `init` I also chose Radix (`--base radix`). Newer versions of the shadcn CLI use Base UI by
default, and this task compares against Radix.

The shadcn Tabs and Dialog appear on the same page, below mine.

**[NOTES.md](NOTES.md)** explains what shadcn/Radix does that mine doesn't. In short:

1. It hides the rest of the page from screen readers while the modal is open.
2. Its focus trap still works after a mouse click outside the modal.
3. It skips hidden buttons when looping focus.
4. It renders the modal at the end of `<body>` (a portal), so parent styles can't cut it off.
5. It stops the page behind the modal from scrolling.
6. With nested modals, Escape closes only the top one.
7. Its Tabs don't block browser shortcuts like Alt+Arrow.
8. Its Tabs support right-to-left languages.
9. Its Tabs support vertical layout and disabled tabs.
